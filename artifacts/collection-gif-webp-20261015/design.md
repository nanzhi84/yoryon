# 合集封面与 GIF WebP：实现前设计

目标：合集列表、会员发现目录及合集详情的封面复用公开图片响应式 WebP；GIF 在公开及会员正文中转成保留动画的 WebP。保留源文件，不改发布、曝光与授权语义，不增加依赖或数据库迁移。

边界与数据流：视图只生成已有四档宽度 URL；公开图片实时权限门禁 → CDN 字节缓存 → API。PNG/JPEG/WebP 继续由 OSS 生成，SVG 原样；GIF 由 API 读取私有原图并以现有 sharp 解码全部帧、输出质量 72 的 WebP。会员媒体在既有授权之后复用 GIF 转码，响应 private/no-store。存储适配器不承担动画处理。

失败方式与边界（先于实现记录）：

- OSS 格式转换会把动画 GIF 变成静态；必须核对全部帧、逐帧延时、循环及浏览器可见动画，不能只看 MIME。
- 真实 GIF 验收发现最大有限播放次数 65536 会在默认 WebP 编码时溢出成无限；显式传递循环数，并将这一 WebP 无法表达的极值收敛到 65535。其余有限次数和无限循环不变。
- 旧 GIF 的 CDN 字节与 ETag 不能让新请求继续得到原 GIF；公开 URL 从 v1 推进 v2，移除旧内部路径。源站 ETag 前缀维持 image-v1 以允许 API/Web 滚动发布，URI 已隔离新的字节缓存。
- 合集列表与详情应按实际容器宽度、设备像素比选择变体，保持方形展示与现有链接语义；检查移动和桌面。
- 独立审查发现合集上传原本合法支持 AVIF，但公开图片白名单没有 AVIF；随封面切换补入既有 OSS/FS WebP 路径，避免合法封面从可读变 403，不改变上传格式入口。
- GIF 输入超 20 MiB、总解码像素超 1600 万或帧数超 500 时明确拒绝；单进程同时只处理一个 GIF，排队最多四个，等待/回源共享 12 秒截止时间，原生转换最多 5 秒。取消、超限、损坏或忙碌均 no-store，不回退静态图片。
- 相同源图与宽度的并发、多个冷图片、无效宽度、源文件缺失或损坏不得无界排队、泄露签名地址或阻塞后续合法请求。
- 公开转会员/下架后，原 URL、条件请求与暖缓存仍受实时门禁约束；未授权会员 GIF 不触发转码。SVG 字节与渲染不变。

验收：独立子代理在隔离数据库、FS、配置与 Mailpit 下，临时 CLI/API/SQL 操作加真实浏览器，核对实际像素/字节/动画/授权及清理。记录环境、命令与可重复生成证据，不维护固定测试程序。主代理执行 pnpm typecheck 和隔离 API 下 pnpm build；构建不代替业务验收。

发布：PR → 独立审核与验收 → 合并 → 构建 linux/amd64 API 并验证原生 sharp → 备份生产现状 → API 更新 → 对应合并提交的 Vercel 生产发布 → 线上合集与图片字节/缓存/浏览器验证。生产只读核验，不创建业务测试数据。回滚使用先前 API 镜像与 Vercel deployment；原图与数据库无需恢复。
