# Issue 26 前端设计与失败方式

数据流：公开合集目录 API → 服务端介绍与目录 → 浏览器校验定位 → 单篇正文权限确认 → 本地位置与合集流程计时。权限凭证不从定位或 URL 派生。封面走已有媒体入口。

本地定位只保存 v1、稳定 chapterId、updatedAt，按合集稳定 ID 分组；解析/配额失败降级。多标签监听 storage。后台、预览、加载失败、预取不写位置。当前发布目录校验本地 ID，撤回/删除/移出清理定位；会员到期仍可定位，权限接口控制正文。

合集流程由根布局持有，带随机流程 ID 的内部 Link 传递归属。刷新、外部直达或离开链路不复用旧流程。目录 View 独立计数，Read 只累计目录与已授权实际正文前台展示时间，跨章累计到 10 秒一次。章节自身指标保持独立。

失败边界：多合集上下文伪造、旧缓存目录、权限请求失败与动态正文未完成、存储损坏/禁用/配额、首尾/空目录、重复 effect、后台切换、导航加载期间计时、返回目录去重、跨独立流程时间拼接。

合并约束：Vercel main Git deploymentEnabled=false，当前生产版本保持不发布；以后部署需用户明确授权。
