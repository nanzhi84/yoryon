# 个人资料设计图落实

用户已批准静态图，并请求修改实际页面与本地预览。仅个人资料视图/Avatar尺寸调整；不改API、认证、会员或其他页面样式。不做源码/数据库大备份。使用现有隔离服务/数据库，当前用户localhost会话不动。

## 排版与数据流

- SiteHeader、单栏/页面同背景保持；main顶部20px、h1 24px/32px。
- h1下8px显示只读登录用户名，12px/20px。再隔20px放头像行：64px头像、16px横向间距，右侧头像标题14px/20px、上传/更换按钮44px、格式提示12px/20px、上传后自动保存。已有头像时保留移除操作。
- 头像区后24px加一条淡细线，线后24px是展示名称表单：标签14px/20px，间距8px，输入44px高/15px/无shadow；再8px提示1–40字，用于评论和会员问答；再20px保存按钮160×44/14px。反馈在按钮下，role alert/status。
- file input隐藏，由可聚焦的原生button打开选择器；保留 PNG/JPEG/WebP、2MB、本机头像上传/居中裁切为320方形后立即保存的API语义。取消选择不写入；同一文件可重选；不可接受类型/大小提供可见错误。
- 名称PATCH与头像POST/DELETE仍调用原接口；pending标记具体操作，网络15秒有界超时，卸载取消；控件请求期间禁用。头像操作更新头像而保留尚未保存的name草稿，避免独立上传清除输入。
- 复用Avatar：增加28/64两个实际尺寸，默认28使评论等原用途保持；不是全站头像风格修改。加载/匿名/失败重试仍可达。

## 实现前的失败方式/边界

无头像/有头像64px与替换/删除；输入/上传/保存的键盘焦点；名称持久化与只读登录用户名；头像操作后未保存名称保留；合法JPG解码/裁切/字节响应；错误类型/过大文件/接口失败的反馈和恢复；初始GET匿名/加载失败与重试。UI与API的数据流要实际核对，不能用build或HTTP200独立代替。

## 隔离验收

Chrome控制当前不可用；内置Browser在127.0.0.1:3015保持匿名，而localhost:3015为用户已登录（仅查看了菜单，没有更改认证）。BFF Cookie host-only，现有ALLOWED_ORIGINS已含两个回环域名，无配置/安全改动。用127.0.0.1自己的隐藏tab和临时普通active用户走真实UI，不借用/覆盖用户会话，不发邮件、不用固定fixture/harness。独立子agent负责临时用户与资产/统计精准清理、SQL/媒体byte核对；若其IAB能力缺失，由主agent执行实际浏览，子agent独立读原始证据并声明执行者。

头像验证使用仓库已有author-avatar.jpg文件，不改源文件。只清自己新建用户/会话/统计与确认新建且无其他引用的头像资产；用户交付preview_test及权益、现有文章/媒体、用户会话保留。凭据/令牌/原始cookie不进工件。运行命令、环境、截图、SQL回执保存本目录。pnpm typecheck/build遵循现有脚本；直接本仓库构建，需短暂停自己的Web以免.active .next改写，API保持。

默认文字头像取首个Unicode码点，避免合法emoji名称被slice(0,1)拆成替换字符；这是头像渲染边界的必要修正，不改名称验证合同。
