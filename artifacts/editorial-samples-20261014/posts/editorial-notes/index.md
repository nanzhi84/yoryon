### 本文要点

1. **从读者路径倒推**把输入、处理与输出放在同一条阅读主线里。
2. **代码拥有自己的区域**长代码独立横向滚动，正文和长链接在阅读列内换行。
3. **把失败情况说清楚**用嵌套列表区分输入、保存与阅读阶段的示意边界。

这是一篇原创排版示例。下面的架构、路径和代码均为教学示意，不描述 Yoryon 当前实现，也不作为部署操作指令。

## 一、从读者看到的结果倒推

一篇文章出现在屏幕上，看起来只需要一个标题、一段文字和几张图片。但读者实际经历的是一条完整路径：打开链接，等待页面，看到正文，向下阅读，在遇到图片时停留，最后选择继续阅读或离开。任何一个环节突然改变，都可能打断原本连贯的注意力。

设计这条路径时，我们可以从一个简单的问题开始：读者是否知道现在发生了什么？加载时需要反馈，内容为空时需要解释，图片失败时仍然应该保留文字，权限发生变化时也不能悄悄消失。稳定的阅读体验来自这些具体的边界，而不仅是第一页看起来漂亮。

> 页面是一份承诺：此刻呈现给读者的内容，应当与这次访问实际允许阅读的内容一致。

### 输入、处理与输出

假设作者提交一份 Markdown 草稿，发布服务检查格式并保存一个新版本，浏览器随后读取这个版本。这个过程可以分成三个阶段：

1. **输入**：标题、正文、图片文件和发布选项。
2. **处理**：校验正文，登记媒体，保存版本，更新公开目录。
3. **输出**：可访问的文章地址和与其对应的媒体引用。

每个阶段都要回答自己的问题。作者提供的是合法输入吗？保存后的媒体能否找到？读者打开的版本与目录里展示的版本一致吗？只有把这些问题放在适当的边界里，后续排障才有清楚的起点。

## 二、代码需要自己的阅读区域

正文应该在自然行宽内换行，但代码有不同的需求。缩进、变量名称和一行表达式的位置都可能影响理解。这里使用一段示意代码，观察等宽字体与横向滚动是否能够保持各自的节奏。

```ts
interface ReadingDocument {
  title: string;
  revision: string;
  paragraphs: string[];
}

function prepareDocument(input: ReadingDocument): ReadingDocument {
  if (!input.title.trim()) throw new Error("title_required");
  if (input.paragraphs.length === 0) throw new Error("body_required");
  return { ...input, title: input.title.trim() };
}

const diagnosticDescription = "This intentionally long source line should remain inside the code block and should not widen the entire reading page on a narrow screen.";
```

这里的 `revision` 只是版本标识的示例。正文中的行内代码应当能够被识别，但不应比周围文字更抢眼；独立代码块则应该与叙述明显区分，让读者在阅读自然语言和阅读程序之间顺畅切换。

### 长链接也属于真实内容

有些资料链接很长，尤其是附带锚点或检索条件时。一个阅读页面不应该要求作者把所有链接都改成短链接，才能保持布局整齐。下面使用明确的示例域名，展示长链接的实际换行效果：

## 三、失败情况应该先有名字

当发布出现异常时，“没有成功”通常不够具体。可能是正文格式不合法，可能是图片还没有完成上传，也可能是文章已经保存，但新的目录还没有更新。它们需要不同的处理方式，也不应被合并成一个模糊的错误提示。

- 输入阶段
  - 标题缺失：让作者补齐标题。
  - 媒体路径无效：指出哪一个引用无法找到。
- 保存阶段
  - 连接中断：保留本次操作结果是否确定的信息。
  - 重复提交：明确复用已有结果还是创建新版本。
- 阅读阶段
  - 图片失败：保留图片说明与重试入口。
  - 正文不可用：说明当前状态，允许读者重新加载。

这份列表是写作示例，并不是一套固定验收脚本。实际项目仍然需要根据自己的领域边界与真实用户路径判断失败，而不能把列表里的项目数量当作质量证明。

## 四、阅读完成之后，还有下一位读者

文章发布完成并不意味着所有读者已经看到了它。有人会从首页进入，有人会从分享链接直接打开，还有人会在几天之后从书签回来。页面需要在这些路径之间保持一致，也需要给最后一页提供明确的出口。

继续阅读可以是一篇相关作品，也可以是回到所属合集。它不必成为一个巨大的推荐区域，只需要让读者知道：这段内容已经结束，如果愿意，下一段内容就在这里。
