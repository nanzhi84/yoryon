## 背景与目标

《实习日记》等日更合集会持续新增章节，逐篇进入首页容易挤占独立文章和短帖的展示空间。为合集提供独立入口和完整阅读路径，同时保持单篇首页展示及免费／会员权限可独立控制。

## 确定的设计

### 导航与发布规则

- 主导航调整为「首页、合集、订阅、探索」。
- 合集从探索中移出；标签仍保留在探索的折叠菜单中，不新增标签主导航。
- 默认发布的独立文章、短帖直接进入首页。
- 先创建合集、再向该合集发布的作品，默认不进入首页；单篇作品可以修改「是否展示在首页」。
- 所属合集、首页展示、阅读权限分别管理，不互相隐式决定。
- 重新发布或编辑作品应保留作者显式设置的首页展示状态。

### 合集信息流

- 合集页采用信息流形式，展示单位为合集，而不是内部文章或短帖。
- 每个合集块展示：标题、封面、简介、最新更新时间。
- 最新更新时间反映合集自身或内部内容的新增、修改，不使用创建／发布时间代替；修改介绍、封面同样属于更新。
- 合集按最新更新时间从新到旧排序，支持置顶，置顶优先。
- 合集不提供评论、点赞、分享／转发入口，也不新增合集级互动统计；仅单篇作品保留现有评论、点赞、分享／转发。

### 合集详情与连续阅读

- 顶部展示合集介绍与唯一阅读按钮：无有效本地阅读记录时显示「开始阅读」，有记录时显示「继续阅读」；不再提供「阅读最新篇」或第二个阅读按钮。
- 下方采用紧凑章节目录，不铺开各篇正文。
- 目录展示标题、日期和免费／会员标识；默认按章节顺序正序，支持切换倒序。
- 初始章节顺序按加入先后确定；编辑既有章节只刷新合集更新时间，不改变章节顺序。
- 「开始阅读」进入首个已发布章节；「继续阅读」返回当前浏览器上次实际阅读的章节，按钮附近可显示「上次读到：章节标题」，目录可标记该章节。这里的“最新阅读位置”是最近一次实际阅读位置，不是合集最近发布的章节，也不是读过章节中的最大序号。
- 阅读记忆使用 `localStorage`，按稳定合集 ID 保存版本号、稳定章节 ID 和更新时间；仅保存定位所需数据，不保存正文、凭证或会员权限，不上报为分析事件。适用于匿名及登录读者的当前浏览器，本期不做账号或跨设备同步；同一浏览器共享本地记录，清除站点数据或结束隐私浏览可能丢失记录。
- 仅在浏览器前台成功展示具有阅读权限的章节正文后写入；预取、SSR、目录点击、加载失败及未解锁预览不更新记录。显式重读旧章节会更新为该章节；新增章节或编辑旧章节不自行改写记录，不把浏览等同于读完。
- 恢复前用当前已发布目录校验本地记录并由章节接口重新校验权限，不信任存储中的 URL 或权限。章节已删除、撤回或不再属于该合集时清除失效定位并退回「开始阅读」；会员失效时继续入口仍可定位该章，但展示正常解锁提示，不泄露正文。存储禁用、配额或解析失败时降级为开始阅读，目录与上下篇仍可用。
- 多标签页以最近一次成功前台展示正文的记录为准，通过 storage 事件同步；客户端读取完成前使用固定尺寸占位，避免先显示错误入口。作品属于多个合集时，从合集进入及上下篇导航需携带并校验合集上下文，分别记忆，不误写其他合集的阅读位置；直接打开作品而无合集上下文时不覆盖任意合集记录。
- 点击章节进入独立阅读页，提供「上一篇、返回合集、下一篇」。首尾章节正确处理无相邻章节的情况。
- 无已发布章节时展示空态，不提供无效阅读入口。

### 阅读权限

- 每篇作品独立设置免费或会员可读。
- 《实习日记》采用前几篇免费、后续章节会员可读；具体免费篇数由作者决定，不写死。
- 合集介绍和已发布章节目录允许未解锁读者浏览；会员章节正文及受保护资源沿用权限校验。
- 本需求不新增合集单独购买要求；只新增浏览器本地章节续读定位，不新增百分比进度、读完判定或更新提醒。

### 合集可观测性：与作品同级的独立统计对象

- 合集在产品语义上作为一个独立作品，沿用现有 `targetKind=collection`、`targetId=合集 ID` 的事件合同，与单篇作品使用一致的曝光、点击、浏览和停留阅读指标；不强制合并 contents / collections 存储模型。
- **曝光 Impression**：合集信息流卡片可视面积至少 50%、连续可见至少 1 秒且页面在前台；每个列表浏览实例对同一合集最多一次。列表来源沿用 `placement=collection_list`。
- **点击 Click**：读者主动点击合集卡片标题、封面或明确的合集详情入口时计入该合集；预取、自动导航、其他非详情入口操作不计入此点击指标。新增封面入口必须接入同一采集路径，避免嵌套链接重复计数。
- **浏览 View**：合集详情页在浏览器真实展示时记录；每个详情页浏览实例最多一次。外部直达、刷新和站内导航均可产生 View；SSR、预取不产生。合集列表页本身不是某个合集的详情浏览。
- **停留阅读 Read**：合集详情页前台累计可见停留达到 10 秒时记录，每个浏览实例最多一次；切后台暂停计时。该指标仅代表介绍／目录页的有效停留，不表示读完合集或任何章节。
- 派生指标与作品一致：`CTR=Clicks/Impressions`、`Read Rate=Reads/Views`；分母为零显示 N/A。曝光与点击在同一列表来源内计算。
- **合集与章节分别归属**：合集介绍／目录页的事件归合集；进入章节后，View/Read 归该单篇作品，不额外给合集增加一次 View/Read。阅读章节、上一篇／下一篇导航不累计到合集四项指标；从章节返回合集并真实展示时可产生新的合集详情浏览。
- 「开始阅读」「继续阅读」、目录章节链接是章节入口，不是合集卡片 Click；本需求不扩展新的章节入口转化指标或合集完读率。
- 合集不展示或统计点赞、评论、转发；单篇作品保留现有互动及统计，与合集流量指标分离，不将打开分享面板当作已成功转发。
- 现有 CLI 的合集总览、排行及 `blog analytics collection <slug> --days <n>` 应继续可用，报表明确区分 work / collection，不把章节表现求和冒充合集表现。
- 后续 Issue #27 的匿名 visitor_id 同样适用于合集与作品；未上线前仅有标签页级 session_id，不能将其称为独立访客人数。本 issue 不重复实现 #27。
- 维持既有 DNT/GPC、失败隔离、有界重试及 event_id 幂等去重；新增信息流、续读及连续阅读交互不得重复发送、伪造曝光或泄露会员正文。

## 实现边界

- 沿用现有文章、短帖、合集、会员与互动能力；需检查首页展示、合集封面及章节续读的现有支持情况，缺失处再补齐；不新增合集级互动。
- 迁移保留既有作品当前首页展示状态，不因作品已经属于合集而批量隐藏；新的默认规则应用于后续在合集内发布的作品。
- 多合集归属时，「是否展示在首页」仍是单篇作品的唯一设置，不由多个合集互相覆盖；共同包含该作品的合集均应反映内容更新。
- 集合更新时间及排序应与发布、修改和缓存失效保持一致。草稿和未授权正文不得通过目录、信息流或缓存泄露。
- 保持已有首页交互、文章独立阅读、加载状态和滚动恢复行为。

## 验收要求

- [ ] 桌面及移动端导航顺序正确；探索中仅移除合集入口，标签折叠行为保持。
- [ ] 新发布独立文章、短帖默认进入首页；合集内新作品默认不进入首页。
- [ ] 单篇可开启／关闭首页展示，重新发布不重置作者设置，既有作品展示状态不被迁移意外改变。
- [ ] 合集信息流完整展示标题、封面、简介、最新更新时间；无封面时布局正常。
- [ ] 创建合集、更新合集资料、新增或编辑章节后，列表更新时间和排序正确；编辑旧章节不改变章节顺序或本地续读目标。
- [ ] 合集置顶优先；取消置顶后恢复按更新时间排序。
- [ ] 合集列表与详情不出现评论、点赞、分享／转发入口；单篇作品现有互动、认证及重复操作约束无回归。
- [ ] 首次只显示「开始阅读」并进入首个已发布章节；成功阅读后只显示「继续阅读」并恢复上次实际阅读章节；目录点击及上下篇像小说阅读一样进入独立章节页，并提供返回合集，正确处理首尾及空态。
- [ ] 同浏览器刷新、关闭重开、多标签页、重读旧章的续读位置正确；新增／编辑章节不改变既有位置。覆盖无记录、损坏记录、存储禁用、撤回／删除章节、会员到期、未解锁预览、预取和加载失败、多合集上下文；记录失败不阻断正常阅读。
- [ ] 免费章节匿名可读；会员章节对未登录、非会员、过期会员正确限制，有效会员可读；直接请求正文或资源也不能绕过权限。
- [ ] 从首页或合集列表进入详情后，返回路径和已有滚动恢复无回归；加载、空态、错误及重试有明确反馈。

- [ ] 合集信息流真实可见后产生曝光，标题／封面／详情入口主动点击产生合集 Click；章节入口和预取不混入 Click，嵌套入口不重复计数。
- [ ] 合集详情直达、刷新、站内进入的 View 及前台累计 10 秒 Read 正确；后台停留不累计，同一浏览实例不重复计数。
- [ ] 通过开始阅读／继续阅读／目录进入章节，及章节上一篇／下一篇／返回合集时，事件目标和数量符合归属规则，章节数据不自动累计到合集。
- [ ] 通过真实浏览器操作后核对隔离数据库及 CLI 的合集总览、单合集报表、排行与派生率；覆盖无事件／零分母、重试去重及 DNT/GPC，不能仅以存在埋点代码或 API 成功证明采集通过。

按项目 AGENTS.md 使用隔离环境和数据，由独立子 agent 通过真实用户路径验收，覆盖发布、缓存、权限和互动边界；将实际命令、环境前提、PASS / FAIL / UNVERIFIED / UNKNOWN 及必要证据记录到 artifacts/<运行名>/，不以构建成功或 HTTP 200 代替业务验收，不新增固定测试程序。
