# 内容点赞与信息流动作

帖子与长文的点赞独立于评论点赞，使用稳定内容 ID；重新发布不丢赞，内容与用户删除级联清理对应点赞行。`content_likes(content_id,user_id)` 为唯一事实来源，计数实时聚合，不新增冗余计数列。

`GET /api/content-interactions?ids=<comma-separated UUIDs>`：最多100个 ID，仅返回已发布作品的评论数（未软删除的根评论与回复）、赞数、当前用户已赞状态与可赞状态。游客也可读取统计。所有响应包含身份状态，统一 `private, no-store`。Feed 目录版本、公开 HTML 与 Data Cache 不保存这些状态。

`PUT /api/content-interactions/:id/like` 与 `DELETE`：必须登录，对已发布内容复用 `canAccess`；付费作品需要当前有效的内容/合集/订阅权益。事务内锁定内容行，再幂等插入/删除；响应返回实际赞数与已赞状态。复用既有 BFF CSRF 保护与每用户点赞限频。本功能不新增内容点赞通知。

前端按列表批次请求，失败提供重试；对旧读取执行取消与代次校验，写入期间禁止旧读取覆盖新状态。零互动显示动作名称，非零显示真实数字；游客点击点赞进入登录并保留当前站内返回地址。评论进入作品详情 `#comments`，使用原生文档锚点导航并保留原 Click 埋点；本地验收发现 Next 客户端首次跨 revision rewrite 导航会丢 fragment，原生导航避免该实际缺陷。转发直接复制本站永久链接，不发送渠道或转发统计；剪贴板失败提供只读可选择链接与重试。

迁移使用项目 `pnpm db:migrate` 入口。上线需先部署 `0012_yielding_paper_doll.sql` 对应迁移，再发布读取新表的 API/Web。本次只在隔离本地预览库迁移；未授权生产发布。回滚代码后可保留新增表作为事实数据，禁止为回滚删除用户已产生的点赞。
