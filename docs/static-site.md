# 静态分支

`codex/static` 将Web站点生成为纯文件，使用已有排版和URL，保留文章、帖子展开、公开合集目录/正倒序/上下篇/续读、标签、全文搜索和图片预览。登录、注册、账号、订阅、兑换、会员问答、通知、评论、点赞和转发模块已移除；静态快照及导出查询也不再携带评论或点赞数据。

原付费文章按照用户选择，仅保留现有匿名公开预览；隐藏正文不进入快照、搜索索引、HTML或浏览器数据。原私有OSS桶不改权限，媒体随静态产物提供。

合集只有在自身为公开且全部已发布成员均可免费阅读全文时才公开。含付费文章的合集整体隐藏：不生成目录，不输出文章中的合集关联、上下篇或站点地图记录。原有单篇文章的阅读范围保持不变。此规则同时用于内容导出和Web构建，旧快照直接构建也不能恢复隐藏合集。

## 构建和预览

仓库内 `content/site.json` 是可公开的内容快照，`content/media.json` 是站内媒体路径映射；`apps/web/public/media/` 保存媒体字节。已有快照可直接构建，无需数据库、API、OSS或其凭据：

```sh
pnpm typecheck
pnpm build
pnpm preview --port 3100
```

打开 `http://127.0.0.1:3100/`。预览只启动本机静态文件服务，不启动API。交付目录是 `apps/web/out/`，该目录可以交给支持目录索引的静态托管平台。`pnpm dev` 仅启动Web开发环境；正式验收使用上面的静态产物预览。

## 更新内容快照

「Vibe Coder速成科普」系列统一使用标签 slug `vibe-coder-crash-course`，显示名称为「Vibe Coder速成科普」。同步或重新发布系列文章时，发布源 frontmatter 的 `tags` 应包含该 slug，并保留文章已有标签；系列入口为 `/tags/vibe-coder-crash-course/`。

执行 `pnpm static:export`。它直接只读连接内容数据库，不依赖阿里云服务器。凭据默认从本机受保护目录 `~/.config/yoryon-production/` 的 `secrets.json`（`database_api_url`）和 `oss-credentials.json`（只读API身份）读取；也可用 `YORYON_STATIC_CONFIG_DIR` 指定同样结构的受保护目录。不要把这些文件复制到仓库或公开产物中。

导出仅读取已发布内容；检查付费预览版本，过滤不允许公开的媒体。媒体下载最多3路并发、每个请求60秒超时、最多2次尝试，核对原始SHA256和尺寸后才提交。完整新内容先写入忽略的暂存目录，再替换导出工具管理的目录，移除不再使用的引用和媒体；失败时保留上一份完整快照。不要并行执行导出和构建。异常退出留下 `.local/static-export.lock` 时，确认没有导出进程后再删除该锁。

篇数与公开合集以当前 `content/site.json` 为准；原有含付费内容的合集继续整体隐藏。媒体清单见同一快照。2026-11-01 验收的快照为 68 篇、2 个公开合集、22 篇公开预览，没有真实音视频或作品引用卡片，因此这些路径只做了静态检查，未声称完成播放/引用业务验收。

## 首次加载

- 页头复用既有favicon.ico内48×48 PNG条目（6044字节），直接提取到`components/header-avatar.png`，不重编码，显示尺寸仍为32px。仅此URL依赖生成data URI，SSR与客户端一致，消除头像请求；原图文件保留供既有公开链接访问。
- 帖子 Markdown 在构建时渲染，客户端只接收已渲染内容并管理展开状态。列表到阅读页的客户端提示只传标题、slug 和日期；静态快照没有动态正文几何布局，加载态继续使用原段落骨架，不引入旧 API 的布局校验依赖。
- 文章链接使用 Next 的可见区域预取，提前读取公开静态 RSC 与共享阅读脚本。快速点击或预取未完成时仍走普通导航/加载反馈；不会预取完整媒体或第三方社交页面。预取会增加少量可能未被阅读的文章数据传输，以换取第一次点击响应。Next 15.5.27 的网络失败回退有静态URL错误，已用pnpm最小依赖补丁修复；原因、验收与移除条件见ADR-0019。
- JS/CSS 使用 Next 的独立哈希资源，跨页复用浏览器缓存。原 CSS 内联和整站脚本内联后处理器已移除，避免每篇都重复携带公共代码与整站内存打包；历史首屏实验保留，当前决策见 [ADR-0022](adr/0022-static-content-scale.md)。Tailwind 只扫描 UI 源文件，内容与 JSON 不参与样式发现。
- 合集介绍在构建时渲染；入口、可见目录项启用预取，接近列表底部时预取下一个 12 条的数据块并自动追加；倒序直接按窗口计算原始序号，不扫描全部目录查编号。
- 实验及现场验收证据：`artifacts/static-performance-20261029/`与`artifacts/static-load-under-1s-20261029/`。本地受控耗时不等于公网SLA；公网DNS/TLS、接入网络和GitHub Pages链路耗时需另行测量。

## 运行边界

- 网页与媒体访问不连接Neon、原API或OSS，不采集并提交原数据库流量埋点。旧统计偏好工具及用户已有本地身份配置保持原样。
- 本地搜索只索引快照中允许阅读的文本，按连续字符串做字面匹配、不区分大小写，搜索状态在当前URL中。结果标题与摘要直接高亮命中文字；每篇只展示正文首处命中片段，遇到第二处命中即截断，省略处用省略号表示。无正文命中时使用描述命中片段，仅标题命中时显示原描述；标题保留完整文字。正文命中定位与高亮在浏览器完成。
- 合集续读使用当前浏览器本地存储，换浏览器或清理数据不会同步；存储不可用时正常浏览。
- 内容撤回/删除需要重新导出、构建和部署，并按所选托管平台的方式撤销旧部署；已经下载的公开文件无法收回。
- GitHub Actions只部署仓库内的公开快照，不修改生产数据库或原API/OSS。本地验收证据位于 `artifacts/static-20261028/`，设计见ADR-0018。

## 内容规模与无限滚动

首页、帖子、合集列表/目录、标签列表/内容按 12 条生成静态数据块，正常交互为无限下滑。首块随 HTML 渲染，接近底部时预取并追加下一块；远离视口的块卸载 DOM 并保留测量高度，返回阅读位置时恢复。已有 `/page/<number>/`、合集 `/reverse/` 和搜索 `page` 深链继续可访问；文章、媒体及 query 参数不变。无 JS 保留静态后续链接，加载失败提供重试。合集续读按章节读取单个 JSON，不下载完整目录。设计见 ADR-0023。

`pnpm build`、`pnpm dev` 会先从快照生成 `apps/web/public/data/static/<快照哈希>/`；该目录忽略提交，并进入最终 `out/`。内容/标签/媒体索引只在构建侧保留。不要并行运行内容导出和构建；异常退出的 `.local/static-data.lock` 需要确认进程结束后再清理。

搜索使用 Worker 和约 64 KiB 目标的文本分片，通过字符索引选择候选，再进行原有连续字符串匹配；每次最多三路读取，主线程按 20 条追加结果，远处结果块卸载 DOM。单篇特别长时允许超过分片目标，保证匹配不被分割。换词取消旧查询；手动重试绕过失败缓存。非 ASCII 大小写查询保守检查全部分片以保持语义。

相对于全站篇数，普通列表和目录首屏、每次追加只处理固定块长；已访问块的高度元数据随浏览进度增长，数据缓存有预算，不能称完整浏览全站的总成本为 O(1)。单篇成本仍取决于正文，全文搜索最坏 O(全部文本)，全站构建与产物大小也会增长。3000 篇真实文档的隔离构建、2932 章目录的浏览器结果及环境前提见 `artifacts/static-scale-20261101/README.md`；无限滚动修订见 `artifacts/static-infinite-20261101/`。该证据不等于公网速度承诺，也不消除静态托管容量限制。

## 社交账号入口

名字旁边的「关注我」统一展示 X、GitHub、公众号、小红书与抖音。桌面使用下拉菜单，小于 640px 时使用底部弹层；改变断点会关闭当前展开层。菜单、弹层支持键盘与 Escape，移动端同时支持关闭按钮及遮罩关闭。

页头菜单由原生popover实现，移动端弹层由原生dialog实现，移除了这两个位置的Radix浮层依赖。菜单保留方向键、首尾导航、Tab退出与焦点归还；弹层包含首尾焦点循环和滚动恢复。需要支持popover/dialog的现代浏览器；具体设计和实际验收范围见ADR-0020。

公开账号唯一配置为 `apps/web/lib/social-links.ts`，与文章快照导出独立。外链在新标签页打开，使用 HTTPS 和 `noopener noreferrer`，只在点击时连接平台。X 使用用户提供的 `@yoryon_`；GitHub、小红书、抖音沿用 `nanzhi84/yoryon-homepage` 首页公开链接。公众号直接显示「釉蓝yoryon」并支持复制；复制失败会提示手动复制或重试，不包含二维码或名片。

## GitHub Pages 发布与域名

工作流为 `.github/workflows/pages.yml`，推送 `codex/static` 后依次执行冻结依赖安装、`pnpm typecheck`、`pnpm build`、上传 `apps/web/out/` 和 Pages 部署。运行不需要数据库、OSS或阿里云凭据。生产域名为 `yoryon.com`，`www.yoryon.com` 跳转至主域名；Pages 设置使用 GitHub Actions 作为发布源。

DNS仅调整主域名与`www`：主域名的A记录指向 `185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`，`www` CNAME指向 `nanzhi84.github.io`。保留邮件验证及其他子域名记录。Pages完成证书签发后启用强制HTTPS；变更后需实际验证域名解析、证书、正文、图片与浏览器交互。

更新内容时，先本地执行 `pnpm static:export`，检查公开边界与媒体，再提交快照和相关媒体并推送。回滚静态版本时，使用 `git revert <引入问题的提交>` 后推送，等待工作流完成并重新验收。DNS迁移前的主域名与`www`记录保存在本机发布工件中，恢复原动态站还需要原托管服务可用；本次部署不停止阿里云服务。
