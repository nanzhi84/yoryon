# ADR-0012：评论根列表使用版本化游标

状态：采纳，2026-10-13。对应 Issue #14。

## 问题

点赞数参与根评论排序。普通 keyset 游标在其他用户改变赞数时可能跳过跨越游标边界的评论；仅按 ID 去重无法发现漏项。完整历史排序快照需要保存每一版列表或长期数据库快照，超过当前评论功能需要。

## 决策

`comment_feed_versions` 独立归属评论模块，记录每件作品的 bigint 单调排序版本。迁移 0008 为已有评论初始化版本，并用评论表触发器在新根、物理删除根、根赞数/时间/ID/删除态/所属作品/层级变化时同事务递增。回复与回复点赞不改变根排序。触发器覆盖领域 API 之外的数据库写入；作品级联删除不留下孤立版本行。

根列表的作品可见性、版本、排序、计数和作者投影在同一短期只读 repeatable-read 事务中读取。游标同时携带作品 ID、版本及排序边界。跨作品游标为 400；版本变化为 409 `cursor_stale`。前端只在当前列表代次接收该失效结果，丢弃旧游标、重读首页并显示排序变化提示，再从新序列继续翻页。请求不持有跨页数据库事务，不保存旧列表快照。

同一版本序列不重复、不跳项；任意跨页排序变化都会明确结束该序列。持续互动可能导致反复重载，这是当前选择的用户体验边界。通知锚点定位遇到序列失效结束定位，保留普通翻页；根与回复定位各自仍有 10 页上界。

## 运维与回滚

先运行迁移再部署 API。0008 仅新增派生表、函数和触发器，不修改评论正文、点赞记录或通知。应用回滚可保留新数据库对象；旧应用会继续递增版本，但不读取它。确认所有消费者均已回滚后可移除触发器、两个函数和派生表；派生版本无需恢复，不应回滚评论或通知事实。迁移需要表和函数创建权限、对既有评论的短期扫描；大量历史评论时应先估算扫描时间。
