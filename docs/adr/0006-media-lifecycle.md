# ADR-0006：媒体存储与发布生命周期 —— 统一私有桶、内容寻址、分阶段发布、延迟 GC

状态：已接受（2026-10-11）；部分取代 ADR-0004

## 背景

原设计为 public/private 双桶：免费媒体进公开桶走 CDN 直链，付费媒体进私有桶走签名 URL。存在两类缺陷：

1. **曝光变化无法安全表达**：媒体的免费/付费状态随内容更新变化（预览区调整、文章取消发布、内容复用关系变化）。双桶下需要跨桶搬移对象，且已发放的公开 URL 无法回收——"付费媒体经历史公开 URL 绕过鉴权"成为制度性漏洞。
2. **发布跨系统无事务**：CLI 发布涉及 OSS 上传与 PostgreSQL 写入，两者无共同事务。若不定义失败与重试语义，会出现 DB 引用不存在的 OSS 对象、部分上传后状态不明、或误删仍被其他内容引用的媒体。

## 决策

1. **统一私有桶**：全部媒体（正文媒体与封面）存于私有桶，一律经 `GET /api/media/:id` 验权后 302 到短期签名 URL（TTL 15 分钟）。任何时刻的访问判断以当前数据为准，不存在可泄露的历史公开 URL。命中免费规则（封面或 `exposure='free'`，身份无关）的 302 允许共享缓存（`public, max-age=300`，必须小于签名 TTL）以保住信息流性能。本条取代 ADR-0004 的双桶与"封面恒 public 桶"规则；ADR-0004 的 exposure 曝光合同继续有效，封面在访问规则中恒视为 free。
2. **内容寻址键**：`oss_key = media/<sha256>.<ext>`。同一文件内容恒定同键——重复上传幂等（上传前 HEAD，存在即跳过）；多篇文章引用同一文件天然共享同一 `media_assets` 行，杜绝重复存储与误删。
3. **分阶段发布**：
   - 阶段 A（准备）：解析 frontmatter/正文 → 计算媒体清单与哈希 → 逐个上传（有限重试）；任一失败即中止，DB 零变更；重跑命令自动续传。
   - 阶段 B（提交）：单个 DB 事务完成 `media_assets` upsert（`ON CONFLICT (oss_key)`）、内容 upsert（按 slug）、`content_media` 替换（含 exposure 重算）、标签与合集成员变更。**事务提交 = 发布成功的唯一判定。**
   - 更新已发布内容同样两阶段；事务提交前旧版本一直在线。
4. **取消发布/删除**：仅 DB 变更（`status='draft'` 或级联删除关联边），OSS 对象不立即删除。
5. **曝光翻转**：仅在事务内更新 `content_media.exposure`，零 OSS 操作。
6. **延迟 GC**（`blog media gc`，默认 dry-run，`--apply` 执行）：清理两类垃圾——① OSS 有对象但 DB 无记录且对象年龄 >24h（上传后事务失败的孤儿）；② `media_assets` 行存在但零引用（无 `content_media` 边、非任何封面）且超过 7 天宽限期。删除前复核引用计数为零；宽限期保护进行中的发布。

失败矩阵：

| 场景 | 行为 |
|---|---|
| 部分媒体上传失败 | 中止，DB 零变更；重跑自动续传 |
| 上传成功 + DB 事务失败 | 孤儿对象暂存；重跑幂等收敛；GC 最终清理 |
| 更新中途失败 | 旧版本保持在线 |
| 取消发布/删除 | 仅 DB 变更；对象留待 GC |
| 曝光翻转 | 事务内改标志，零 OSS 操作 |

## 后果

- 正面：历史公开 URL 泄露路径被制度性消除；发布可安全重试且幂等；媒体跨文复用安全（删除内容只删边）；不引入分布式事务协调器或工作流引擎。
- 代价：所有媒体请求多一跳 302（免费资源由共享缓存缓解）；GC 依赖运维执行（cron + dry-run 审计）；私有桶流量无 CDN 直链成本优势（个人博客规模可接受）。
- 约束：任何代码路径不得生成长期有效的媒体 URL；OSS 对象只允许由 GC 在零引用 + 宽限期后删除；媒体访问控制只经 `/api/media/:id` 的规则集，不得新增绕过路径。

## 修订记录（2026-10-11）：GC 与发布的并发互斥

变更原因：孤儿对象的判定（无 DB 记录 + 年龄 >24h）与发布流程（HEAD 存在即跳过上传，随后提交 DB 引用）存在竞态——GC 若在发布的 HEAD 检查与阶段 B 提交之间删除对象，会产生悬挂引用。重试场景下发布两阶段可能相隔数天，任何时间窗都无法消除该竞态。

补充决策：`blog publish` 与 `blog media gc` 通过 PostgreSQL 会话级 advisory lock（固定 key `hashtextextended('yoryon.media_publish_gc', 0)`）互斥：发布从阶段 A 到阶段 B 提交全程持锁；GC 以 `pg_try_advisory_lock` 尝试获取，失败即跳过本轮（下轮 cron 再试）。会话级锁随进程退出自动释放，无残留锁；两进程本就连同一数据库，零新增基础设施。unpublish / 删除内容不碰 OSS，由 7 天宽限期兼底，无需持锁。E2E 需覆盖 GC 与发布并发执行的场景（架构文档 §13 第 16 条）。
