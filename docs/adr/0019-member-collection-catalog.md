# ADR-0019：会员作品按合集聚合

状态：接受（2026-10-15）。用户要求避免会员作品被同一合集的大量章节铺满，并明确确认“合集聚合＋独立作品”。

订阅页的会员作品区使用新的公开发现目录 `/api/member-feed`。包含至少一篇已发布会员作品的合集以一条入口出现，显示“合集 · 共 N 篇 · M 篇会员”，总数只计已发布内容；合集自身 public/paid 不决定章节权益。不含会员作品的合集不出现在此区。归属任意现有合集的会员作品不再作为独立条目重复出现；没有合集的已发布会员作品逐篇显示。一篇作品属于多个合集时，各合集是不同阅读组织入口，各出现一次。

API 在 repeatable-read 只读事务内先聚合集合，再和独立作品合并分页，避免客户端按单页文章分组导致重复合集和错误分页。合集按 updated_at，独立作品按 published_at / created_at 排序，统一毫秒时间、UUID、kind 降序全序和二十条分页，游标明确校验；草稿不参与计数或列表。目录元数据与公开预览不含会员正文，授权仍由单篇详情实时决定。原 `/api/paid-feed` 保留其外部纯作品协议，首页与标签页也保持纯作品流。

订阅首屏复用 fetchCatalog 的实时目录版本门禁，后续页使用同版本分页。缓存事件投递失败仍能选择当前版本；版本变化返回409并提示刷新。客户端沿用 LoadMore 的取消、15秒超时、失败重试、版本恢复、去重及有限分页请求，新增合集条目类型但不将其混入首页。原 paid-feed 非版本缓存导致本地新会员作品缺失的问题由改用当前目录门禁消除。

合集简介保留完整展示，不加截断或折叠；本地长文案用于查看当前封面并排和窄屏换行表现。会员目录中的合集简介沿用列表三行摘要，与详情完整文案区分。

没有数据库迁移或新权益规则。可将订阅入口切回原 paid-feed 回滚；新目录不修改业务数据。示例内容与长简介只写隔离开发数据库。验收关注同合集多会员章节只出现一次、混合/纯免费/纯会员合集、多合集归属、草稿和撤回、移出合集的独立作品、版本变更和跨页无漏重、公开正文隔离及真实浏览器最终显示。

部署顺序：先上线包含 /api/member-feed 的 API，再上线订阅页。现有首页/合集列表统计 placement 保持原口径，本次不新增订阅列表曝光统计，避免把会员目录混算为 collection_list。
