# ADR-0017: 匿名浏览器身份与首次观察账本

状态：已接受（2026-10-15，Issue #27）

## 背景

sessionStorage 只能关联标签页会话，不能分辨跨会话回访。原始事件保留 365 天，单独扫描原始事件会在清理后误判老身份为新访客。需要最小持久化，同时避免登录关联、设备指纹和伪造历史身份。

## 决策

1. 首次需要采集时创建主机限定、随机 UUID 的第一方 Cookie。Secure、SameSite=Lax、Path=/、180 天，不设置 Domain，不在访问时续期。DNT/GPC 在初始化和投递处均停止采集。Cookie 不可用时仍采集缺省身份事件，本页不逐事件重试生成 UUID。
2. `visitor_id`、`session_id`、`page_view_id` 分别表达浏览器环境、标签页会话、浏览实例。支持 Web Locks 时协调首次 Cookie 创建，投递前重读共享 Cookie；无锁时后续重读收敛，不持有内存 UUID。初始化未完成便离页的事件可以缺省身份。
3. 为原始事件增加可空 `visitor_id`，旧合同缺省仍有效，历史不回填。仅对已识别部分计算独立/新/回访访客，缺省身份显示覆盖情况；没有可识别事件时显示不可计算。
4. 独立最小表 `analytics_visitors(visitor_id, first_seen_at)` 保存首次实际插入有效事件的服务端时间。与事件写入同事务，重复 event_id 不产生账本记录；并发 upsert 取最早时间。表不保存最后访问、来源、账号或设备信息，不作为新汇总表或缓存。
5. 账本长期保留，原始事件 prune 和目标删除不影响 first_seen。否则无法在长期回访和可选的大窗口中维持首次观察定义。整体删除统计身份历史须显式同时处理账本和事件，删除会重置语义；Cookie 到期不复建身份、不续期、不关联新 UUID。
6. CLI 全站窗口 `[from,to)` 中活跃且 first_seen 位于窗口内为新访客，first_seen < from 为回访；窗口内首次出现后再次访问仍是新访客。每位身份仅统计不同非空 session 数，注明标签页会话及缺省事件；输出本次临时行号，不输出 UUID。
7. 日志、公开响应与验收工件不含持久身份。Drizzle 持久化异常可能带 SQL 参数，采集 API 捕获该异常，仅记录静态错误上下文与请求 ID。

## 取舍与后果

- Cookie 身份表示浏览器环境，不是准确人数。清除 Cookie、到期、更换环境会产生新身份，共享浏览器会合并；该局限在文档和报表显式说明。
- 新增最小账本打破 V1 的字面单表限制，但避免汇总表、后台任务、指纹或原始事件永久保留。账本随身份量增长，只有 UUID 和时间两个字段。
- 无 Web Locks 浏览器的极短首次竞态可能产生少量初始不同身份，但后续投递读取持久 Cookie，不会长期分叉；该边界需与支持锁的真实浏览器验收分开陈述。
- Secure Cookie 需要安全上下文或浏览器对 localhost 的例外。普通 HTTP 主机不能保存时身份缺省，统计不能阻塞阅读；本次不改变站点部署协议。
