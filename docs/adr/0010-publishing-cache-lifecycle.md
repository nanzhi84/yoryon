# ADR-0010：发布缓存生命周期

目录范围版本、预热范围与 verified 的当前语义见 [ADR-0021](0021-scoped-catalog-cache.md)；下文保留原决策背景。

状态：实现完成；本地与云端验收结果分别记录在验收工件中。

## 目标、职责与数据流

CLI/core 管理业务写入，DB 保存内容与同事务 outbox；web 仅消费已签名事件、失效 tags/paths；投递器在提交后刷新并匿名 GET 验证公开页面。协议标识放在 config 子路径，web 不依赖 DB/core。

公开数据失败必须抛错，不生成空列表/部分 sitemap。默认 24h 是兜底，正常可见性由事件驱动。所有写入口记录旧、新标签与合集。投递串行持有发布锁，失败持久化，最多三次自动尝试，人工恢复复用同一事件。

## 编码前的失败方式与边界

- 提交后退出、投递超时：outbox 保留 pending/failed，不报告页面验收成功。
- 重复、乱序事件：失效只读取当前业务数据，不写回旧正文；event_id 由持久化 outbox 认领。
- 新 slug/tag 首访 404：精确清理路径及数据 tag，验证真实 GET。
- 标签/合集替换与删除：事务内保存删除前的关联，不能只在提交后查询。
- API 临时故障：不得覆盖最后成功页面为空态或部分 sitemap。
- 恢复/重建：同 slug 新 revision；旧事件不能恢复旧正文。
- 权限收紧：普通 ISR/purge 的 STALE 回退及生成竞态不满足撤销合同；采用缓存前版本门禁与不可变 UUID 缓存 key；旧 key 直接访问同样被阻断。不能用本地通过宣称 CDN 撤销通过。
- 签名媒体：不扩展共享缓存范围；已签发 URL 的最大剩余有效期为 MEDIA_SIGN_TTL，已下载副本无法召回。

## 验收

复用真实 CLI、隔离 PG/FS、Next production server、浏览器路径；新增长 TTL 场景证明业务事件而非 1s 到期带来更新。工件记录事件状态、GET 断言、运行前提、精确提交和脱敏证据。云端缓存命中、撤销和性能单独报告。

## 投递与有效时点

同事务生成内容 UUID revision 与 outbox，API 门禁只从当前数据库重建，不采用事件中的旧状态。投递失败保留 pending/failed；`blog cache status/retry` 人工恢复，恢复复用同一事件。消费者仅跳过已 verified 的事件，未完成预热的重试重新失效，覆盖确认后 web 退出的窗口。API 单进程内刷新串行，避免旧查询覆盖新快照。

每次变更最多 100 个白名单目标；超限/非法目标在事务提交前拒绝，不能写成成功。预热串行、每请求 10s、每事件最多 3 次尝试，每轮最多 100 事件。正常少量目标的可见性目标 60s，最坏失败处理可能更久；不能以退出码代替事件状态。公开详情比较当前 updatedAt，首页/标签/合集列表比较 catalog version，sitemap 比较全部成员；仅 HTTP 200 不足以 verified。

回滚 API 前必须先回滚 web 到全动态详情部署，停止发布并处理 pending 事件；不能让静态 web 连接缺少门禁的旧 API。新增迁移是增量字段/表，旧 API 可读取旧字段；恢复新版本后运行 cache retry。生产沿用单实例，禁止在无共享门禁时扩容。

2026-10-14 阅读入口修订：canonical `/p` 每请求在异步页面内核验当前revision，再读取revision-keyed公开Data Cache。骨架可先显示，正文在校验后输出；不再使用Middleware覆写请求头。内部 `/render` 的Middleware门禁及ISR仍保留。文章Link只自动partial预取空骨架，不预取完整正文。发布/失效目标、事件状态、UUID轮换、私有正文与媒体合同不变；缓存拓扑与浏览器撤销验收见ADR-0003的2026-10-14修订。
