# ADR-0020：文章、帖子与合集入口统一

状态：已接受（2026-10-15，用户提供设计图并确认实现）。

## 目标与边界

首页只列文章，帖子独立为首页和合集之间的 tab，合集保留 /c。文章与合集用相同图文入口，正文媒体在详情消费。用户最终确认：帖子完整保持原有信息流展示，包括媒体和原地展开／收起；合集只包含文章。

## 决策与数据流

- `/` → `/api/feed` 只查询 article；`/posts` → `/api/post-feed` 只查询 post。先过滤类型、发布状态及原 showInHome 展示开关，再按置顶、毫秒时间、ID 分页。保留现有开关含义，不批量改持久化数据。
- 文章、合集标题和简介位于左侧，右侧封面固定 4:3，桌面 112×84、窄屏 88×66。缺封面时使用同尺寸图标占位；不重写原媒体文件，不改变正文图片比例。日期／合集篇数位于左侧简介下方，互动仍在图文区下方。
- 帖子完整复用原 PostEntry、Markdown 与媒体展示，包括本地／远端展开和收起、付费预览、失败重试、取消与资源释放。匿名权限投影、有界列表传输及浏览记忆规则沿用原有实现。日期位于内容下方，并保留详情链接。
- 合集目录、篇数、上下篇导航与会员合集聚合仅包含已发布文章；旧 post 关系不再对外呈现，但不自动删除数据库关系或更改已持久化权益。新发布拒绝 post 的非空 collections，要求作者明确移除合集设置或改为 article。会员目录中旧合集帖子作为独立作品呈现，避免因隐藏的旧关系而丢失入口。
- 完整详情与作品内部引用保持原有媒体组合、权限与播放器生命周期。
- 帖子曝光与五秒可见／主动展开 read 口径保留，来源改为 post_feed；read 仍是有效停留，不代表完读。详情仍不新增帖子 view/read。CLI 同时统计旧 home_feed 与新 post_feed 的帖子 impression/read，历史记录不改写。placement 是 text 列，仅更新协议／TypeScript 枚举，无数据库迁移。

## 并发、缓存和故障

首屏和追加页统一使用 entry-v5 缓存键；sessionStorage 列表记忆使用 feed-v5，避免复用旧混合列表。文章／帖子游标携带类型，拒绝跨列表或旧格式游标并提示刷新；目录版本快照、并发互斥、15 秒超时、失败重试与滚动恢复沿用原有机制。

无封面保持稳定几何空间。帖子展开失败保留原内容并提供重试，卸载或取消时中断请求；付费展开由详情授权，不改变预览权益。媒体-only 帖子继续直接展示媒体。

## 验证与回滚

以隔离数据库、FS 存储与 API 完成分页、手机、展开／收起、详情多媒体、付费授权与版本失效验收。实际命令、回执和独立判断放在 artifacts/unified-entry-20261015/；不增加固定测试套件。

本次不迁移内容或媒体数据；回滚应用即可恢复原入口。旧游标／缓存应刷新，不新增内部兼容渲染或双写。
