# ADR-0020：静态导出的初始脚本合并传输

日期：2026-10-29。基线：c8ce4dc。目标：降低静态首页的必需资源完成时间，保留现有内容、交互与Next路由机制。

## 问题与选择

上一轮公网三次load为1.47–1.74秒。12个初始脚本约169KB gzip，头像虽然早被发现，却在请求开始前等待669–877ms。没有明显主线程长任务。仅调整头像无法解决已经超过1秒的脚本尾部。

在`next build`导出后执行`scripts/bundle-static-scripts.mjs`，按每页原文档顺序将其已经需要的经典async脚本合成一个内容寻址文件，前置preload指向该文件。该步骤使用项目已有版本的htmlparser2读取精确源区间，只改选定的脚本与preload标签，正文、主题初始化、nomodule兼容脚本、RSC内联数据和样式保持原字节。

每段webpack注册脚本保留独立函数作用域，并以self作为顶层this，防止前一段的`use strict`影响后续脚本。第一轮直接拼接曾实际触发Next的`_N_E`严格模式异常，失败证据和修复后真实路径均保留。仅支持当前固定Next版本的webpack注册/运行时格式；未知属性、缺少bootstrap/preload、越界或缺失资产等导致构建失败。框架升级必须重新核对格式与行为，不能删除校验绕过失败。

原始chunk与RSC文件保留，由Next继续管理动态导入、预取、客户端导航和失败回退。应用不新增客户端加载器、定时延后脚本或依赖load事件的初始化。当前74个导出HTML共用6个合成包；首页原有12次初始JS请求变为1次。

## 缓存与兼容代价

同一模板使用内容相同的合成包，普通SPA导航继续复用已注册模块，只加载其缺少的路由chunk。整页跨模板访问可能需要重新下载合成包中的共有框架，HTTP缓存复用粒度变粗；本次优先改善首次访问，不能宣称所有热缓存流量也减少。原始chunk保留不等于永久保留历史部署资产，既有Pages跨版本缓存边界不变。

JS失败时仍可阅读服务端生成的正文和使用普通链接；需要JS的菜单/主题等保持原有依赖。CSP/SRI或新的script属性须明确适配后再构建。本次没有引入第三方运行时服务。

## 验收与回退

证据位于`artifacts/static-load-under-1s-20261029/`。使用干净worktree避免本机未发布文件影响构建。固定网络/CPU对照与公网冷HTTP缓存结果分开；同时核对load、最后初始脚本、头像、FCP/LCP、早点击和预取完成后点击，禁止通过延后必需资源伪造load达标。

独立核对完整HTML、原资产、脚本顺序与作用域；真实浏览器覆盖搜索高亮、图解预览、主题/窄屏菜单、帖子展开、导航、RSC失败及脚本不可用时的静态阅读。浏览器HTTP缓存与跨模板传输量另列，不把本地no-cache预览当作公网缓存验收。

PERF-02：现场复现展开长帖后进入详情再返回时，scrollY从1798变为2290；c8ce4dc基线与候选一致，展开状态保留。精确位置恢复属于既有缺陷，需在后续滚动恢复任务处理，本次不将其标为通过，也不混入传输打包改动。

若打包行为不兼容，撤销本ADR对应提交中的构建步骤、脚本与直接构建依赖，按原Next导出流程重建发布；无需内容/数据迁移。ADR-0019中的RSC失败回退补丁仍然保留。
