# ADR-0004：媒体曝光合同 —— 发布期计算 exposure 字段

状态：已接受（2026-10-11 注记：桶存储策略由 ADR-0006 取代；exposure 曝光合同继续有效）

## 背景

仅把付费内容的媒体放入 private 桶不足以正确表达访问边界：

- 付费文章的**免费预览区**可能包含图片/视频，这些媒体必须对匿名读者可加载——"private 桶一律要权益"会把预览区的图也挡掉。
- 反过来，即使私有媒体的 URL 或 ID 被猜到，也不能绕过付费墙。
- 同一媒体可能被多篇可见性不同的内容引用，"媒体是否免费"不是媒体自身的固有属性，而是它**在每个引用上下文中的位置**决定的。

## 决策

把"媒体是否在免费预览区"从运行时推断改为**发布期计算并持久化的数据合同**：

1. `content_media` 关联表增加 `exposure: 'free' | 'paid'` 字段。
2. 曝光值由预览截断函数（packages/core 唯一实现）计算：该函数输出 `{ freeAst, paidAst, freeMediaIds }`，发布/更新内容时据 `freeMediaIds` 写入曝光标记——阅读裁剪与曝光计算同源，不会漂移。
3. `GET /api/media/:id` 的放行规则（满足任一）：
   - 媒体在任一已发布内容中 `exposure='free'` → 匿名可访问；
   - 当前用户对任一引用该媒体的内容通过 `canAccess` → 放行；
   - 否则 403。
4. 语义细则：
   - 同一媒体被多处引用时 `free` 优先（它事实上已公开）；
   - 截断以块为原子单位，媒体块绝不截一半；
   - 封面图恒进 public 桶（出现于公开信息流）；【已由 ADR-0006 取代：统一私有桶，封面恒视为 free】
   - 独立付费图片/视频/音频内容的媒体本体恒为 paid（v1 不做媒体自身的百分比预览）；
   - 媒体 ID 使用不可枚举 UUID，URL 猜测不构成攻击面。

## 后果

- 正面：预览区媒体与付费区媒体的边界成为显式、可查询、可测试的数据；阅读路径无需在每次请求时重跑截断。
- 代价：发布/更新内容必须重算曝光（已由发布管线自动完成）；媒体复用语义（free 优先）需内容作者知悉。
- 约束：媒体访问控制只允许经由 `/api/media/:id` 的三条规则，不得新增绕过路径；截断函数的任何修改必须同步验证曝光计算。

## 修订记录（2026-10-11）

- **被取代部分**：双桶存储与"封面恒进 public 桶"规则由 [ADR-0006](0006-media-lifecycle.md) 取代——所有媒体统一私有桶、经签名 URL 访问，封面在访问规则中恒视为 free。曝光随内容更新变化时不再需要跨桶搬移，历史公开 URL 泄露路径被消除。
- **继续有效**：本 ADR 的核心决策不变——`exposure` 字段由发布期截断函数计算并持久化、媒体访问放行规则（免费曝光/权益/否则 403）、free 优先、块原子截断、UUID 不可枚举。放行响应的缓存区分见 ADR-0003 修订。
